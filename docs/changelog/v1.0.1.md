在线更新失败等问题。

## ⚡ 破坏性变更

- 无

## ✨ 新增功能

### 定时消息持久化

- 定时消息（内容、顺序、轮转指针）随 `server_state.json` 持久化,**重启不再丢失**
- 更换 Bot Cookie 时定时消息自动迁移,不再被清空
- 添加/编辑/删除/移动/跳过/立即发送全部即时落盘
- 恢复时 Bot 处于停用状态则不启动计时循环,启用时自动补启动

## 🐛 Bug 修复

### 多 worker 状态分裂（刷新偶发数据回退）

- 删除直播间后刷新偶发"仍然存在" → 跨 worker 同步补全删除路径（含断连清理）
- 启用/停用 Bot 后刷新偶发显示旧状态 → Bot 启用标记与删除操作跨 worker 同步
- 过期内存保存会"复活"已删除的直播间 → 保存前强制同步,保存后自记录 mtime
- 停用直播间从未真正断开连接（`quit()` 被启用检查拦截,异常被静默吞掉）→ 新增无条件断开的 `disconnect()`
- 直播间启用/停用标记未同步到实例 → 刷新后显示与实际不一致

### 在线更新

- 部署包内层镜像按精确名匹配,带顶层目录前缀时误报「缺少 mismiss-docker.tar.gz」→ 改为与 docker-compose.yml 一致的 endswith 匹配
- `mismiss-1.0.0-docker.tar.gz` 资产为裸镜像归档导致「缺少 docker-compose.yml」→ 重新打包并发布 v1.0.1 资产
- 部署包改为扁平结构（无顶层目录）→ 旧版服务器亦可通过在线更新自愈,无需 SSH
- 长请求被 gunicorn 30s 默认超时杀掉（「请求失败」,需多次重试）→ 容器内 `--timeout 1800`
- Windows 打包脚本产出 `.tar.gz` 时 Git tar 不支持盘符路径 → 显式调用系统 bsdtar

### 配置写入

- `update` 配置保存与定时消息间隔写入为直接读写 `config.yml`,并发时可能互相覆盖、写一半损坏 → 统一原子写入（tmp + replace）

## 🔧 改进优化

- **默认单 worker 部署**（`MISMISS_WORKERS=1`）:直播间连接、Bot 定时器、插件实例均为单实例资源,多进程会导致连接重复、事件分裂、状态不一致;单进程 + 异步已足够本应用的 API 负载
- 跨 worker 同步机制保留,多 worker 手动开启时继续兜底(限制已写入文档)
- Windows 打包流程同时产出 `.zip` 与 `.tar.gz` 两种部署包格式
- 新增本地回归测试 `test/test_cross_worker_sync.py`、`test/test_timer_persist.py`(Docker 内运行)
