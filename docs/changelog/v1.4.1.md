# 🔧 MisMiss v1.4.1 — 直播间看得见 · 补偿发得动 · 面板存得下

<div align="center">

**总览直接看开播状态 · 一键跳进直播间 · 批量补偿时长 · Docker 保存设置不再 500**

</div>

---

v1.4.1 是一次**补齐直播间与账户运维**的版本：

- **开播状态修好了**——此前「主播已开播」和「显示未开播」经常对不上，得手动刷新才同步；
  现在总览页就能直接看到每个直播间是否在播
- **跳转与绑定直播间**——一键跳到猫耳直播间页面；绑定/更换时可以直接**粘贴直播间链接**
- **批量补偿时长**——按条件筛账户，一次给一批人补天数
- **Docker 部署的「保存设置」不再报 500**
- 还有全局消息、批量补偿、多选日志筛选、自绘下拉框若干

## ✨ 新增功能

### 直播间

- **总览显示开播状态**——账户卡片上「开播中 / 未开播」与「已连接 / 未连接」并列显示。
  两者不是一回事：连着但没开播是常态
- **跳转直播间**——总览卡片与账户详情页各有一个入口，一键在猫耳打开
  `https://fm.missevan.com/live/<直播间 ID>`
- **按链接绑定/更换**——绑定与更换直播间的输入框现在**直接粘贴直播间链接**即可
  （带协议头、`www`、结尾斜杠、查询串、参数都行），当然也仍然接受裸数字

### 账户

- **批量补偿时长**——账户总览的「批量补偿」：默认**全选**，用选项**排除**不想要的
  （排除已过期 / 排除未过期 / 排除剩余天数多于 N 天 / 逐个取消勾选）。
  走「预览 → 二次确认列出将要补谁 → 执行」，确认前能看到完整的受影响名单
- **创建账户的默认凭据**——用户名默认 `user_<账户号>`、密码默认 `user123`，两者都还能改

### 面板

- **全局消息**——「服务器设置」页新增卡片，用各账户的机器人向所有**已启用且正在开播**
  的直播间广播一条自定义消息（与更新提示走同一条通道）
- **日志按账户多选筛选**——日志页的账户筛选从只能选一个改为多选，可同时看几个账户；
  长按不再需要来回切换
- **自绘下拉框**——全站下拉不再使用系统原生控件，展开列表跟随应用主题（深色界面里
  不再弹出亮色一块）

## 🐛 Bug 修复

- **「未开播」与「主播离线」状态不同步**——开播/下播由平台通过 WebSocket 明确告知，
  但此前只异步去查一次房间信息接口，而「主播在线」是同步改的：于是出现「主播已开播
  但仍显示未开播」，要等接口回来才对上；**接口一旦失败就永远停在旧值，只有手动刷新
  才对得上**。现改为收到开播/下播通知时**同步**更新状态，房间信息接口只负责补齐人数、
  封面等展示字段
- **Docker 部署下面板的设置根本存不下来**——`docker-compose.yml` 把 `config.yml`
  以只读（`:ro`）方式挂载，而「更新源设置 / 更新提示消息 / 日志等级 / 端口」四个端点
  都要写回这个文件；写入抛出的 `PermissionError` 没有被捕获，面板只看到无信息的 500，
  用户无从判断是自己填错了还是部署方式不对。现改为读写挂载（更新流程本身会跳过覆盖
  `config.yml`，容器可写不会被发布包冲掉用户配置），并让写入失败的端点返回带**文件路径
  与处理办法**的可读报错。顺带堵掉一个数据丢失隐患：原先读取配置失败会退回空字典再写回，
  等于把文件里其余配置全部抹掉，现在改为报错中止
- **「安装后自动启用」的控件形态不一致**——它是复选框，而全站其它「点了立即生效」的
  设置都是开关按钮，容易让人以为改完还要再点保存。现统一为开关（行为本来就是即时的：
  拨动即通过接口落盘，失败会回滚）

## 🔧 改进优化

- **手机上不再三行按钮**——插件库头部原来标题被压成四行、五个操作排三行；现窄屏下
  标题与操作分行、次要操作只留图标，压到一行。日志页同理：级别筛选、账户筛选、
  三个操作、搜索原本各占一行，现折叠为「搜索 + 筛选」一行，筛选区一点即开
- **更新提示开关点击即生效**——不再需要额外点一次保存

## ⚠️ 升级注意

- **Docker 部署需要用上新的 `docker-compose.yml`**——若你此前保存设置遇到 500，
  根因是 `config.yml` 被只读挂载。在线升级到本版本会自动带上修正后的 compose 文件，
  并在重建容器时生效；想立刻恢复也可以自己在宿主机把 `config.yml` 那行末尾的 `:ro`
  去掉，再执行一次 `docker compose up -d`
- **「开播状态」是新字段，与「已连接」含义不同**——`room_streaming` 表示主播是否在播，
  `room_connected` 表示机器人是否连上了直播间。连着但没开播属正常状态
- **批量补偿只处理非永久账户**——永久账户加天数没有意义，会被自动排除并计入「跳过」，
  在确认弹窗里能看到原因
