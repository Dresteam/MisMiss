## 1. 猜灯谜（latern_riddle）

### 玩法

机器人在直播间出灯谜，观众抢答，答对者得分。

```
🎐 灯谜来啦！
谜面：小时穿黑衣，大时穿白袍，水里过日子，岸上来睡觉（打一动物）
⏰ 60 秒内抢答，发送【猜 谜底】参与～

@小明 猜：青蛙       ← 观众抢答
❌ 再想想～

@小红 猜：鸭子
🎉 恭喜 @小红 答对啦！谜底就是「鸭子」
```

### 指令设计

| 指令 | 权限 | 说明 |
|------|------|------|
| `出灯谜` | 授权用户 | 出题（可选参数指定难度/分类） |
| `猜 <答案>` / `猜谜 <答案>` | 全员 | 抢答 |
| `提示` | 授权用户 | 放出提示（如首字、字数） |
| `公布` / `跳过` | 授权用户 | 直接公布答案并结束本题 |
| `灯谜榜` | 全员 | 本场答对排行（可选） |

### 实现要点

- **题库**：打包 `riddles.json`（谜面 / 谜底 / 提示 / 分类 / 难度），随插件分发，参考 `qiuqian/lots.json` 的打包方式；标注来源与许可
- **答案匹配容错**：去空格、全半角归一、忽略大小写；支持同义答案（`"鸭子|鸭"` 多谜底写法）
- **抢答去重**：同一人同一题只判一次；答错可选「冷场」提示（同一人连错 3 次静默）
- **计时**：`asyncio.create_task` + `sleep`，到点自动公布（参考 `number_bomb` 的计时器写法）；插件 `terminate()` 需取消未完成的计时任务
- **计分**：可选接入 `gift_thanks` 的白/黑榜体系，或自带「本场答对数」榜（内存态，`数字炸弹` 式重置）
- **防刷屏**：答错只在 @用户 维度回复，不广播（避免刷屏）；连错可静默

### 配置项草案

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `cmd_start` / `cmd_guess` / `cmd_hint` | `出灯谜` / `猜` / `提示` | 指令名 |
| `timeout` | `60` | 答题时限（秒），0 = 不限时 |
| `score_enabled` | `true` | 是否计分 |
| `wrong_reply` / `right_reply` | 文案模板 | 答错/答对文案 |
| `categories` | `[]` | 允许的题目分类（空=全部） |

### 成本与风险

- 主要成本：**题库准备**（建议先做 100 题左右，可后续通过 Web UI 增删）
- 风险：同音/近义答案漏判 → 用「多谜底 + 容错归一」缓解

## 2. 恋爱日记（love_diary）

### 玩法

发送指令，机器人以「日记」口吻随机生成一段表白/情话。

```
📔 机器人的恋爱日记
━━━━━━━━━━━━━━━━
9月21日　晴　有风

今天又见到你了。
你笑起来的样子，让我这台只会算数的机器，
第一次觉得「喜欢」是个不需要理由的程序。

——来自一只偷偷喜欢你的机器人
━━━━━━━━━━━━━━━━
@小明
```

### 指令设计

| 指令 | 说明 |
|------|------|
| `恋爱日记` / `表白` / `情话` | 随机生成一段（别名可配置） |
| `恋爱日记 甜` | 可选风格参数：甜 / 土味 / 文艺 / 沙雕（分风格文案池） |

### 实现要点

- **生成方式**：模板 + 词语槽位拼装（无需外部 API，离线可用）
  - 句库分层：`开头` → `主体` → `结尾`，随机拼接
  - 槽位：`{称呼}` `{天气}` `{动作}` 等，从词库随机替换
  - 例：`今天{天气}，我又{动作}了。{主体句}` → 每段都是新组合，重复率低
- **日记体包装**：日期（当天真实日期）+ 天气（随机）+ 署名，用装饰线分隔（参考 `gift_thanks` 的 header/footer 模板）
- **可选增强**：接入 LLM API 生成（需配置 API Key + 失败回退本地模板）——建议先做本地版，LLM 作为可选项
- **去重**：同一用户短时间内不重复同一段（记录最近 N 条）

### 配置项草案

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `cmd_diary` / `cmd_aliases` | `恋爱日记` / `["表白","情话"]` | 指令名 |
| `style` | `甜` | 默认风格（甜/土味/文艺/沙雕） |
| `header` / `footer` | 装饰模板 | 日记外框 |
| `date_format` | `{m}月{d}日` | 日期格式 |

### 成本与风险

- 成本低：核心是文案库，先写 30~50 组句子即可上线，后续可扩充
- 风险：文案重复感 → 用「多段拼接 + 槽位替换」把组合数拉到很大

## 3. 击鼓传花（pass_parcel）

### 玩法

「花」（随机数字）在玩家手中传递，限时内必须传给下一位，**结束时花在谁手上谁就输**。
参考 missevanbot 的 `handlers/game/pass_parcel.go`。

```
🔨 击鼓传花开始！本轮顺序：
1. 小明
2. 小红
3. 小刚

需要输入的数字：48213      ← 只有当前玩家能看到「花」
👉 轮到 @小明，请在 1 分钟内输入上面的数字传下去～

@小明 48213                 ← 当前玩家输入正确 → 传给下一位
需要输入的数字：95704
👉 轮到 @小红，请在 1 分钟内输入上面的数字传下去～

（超时）
⏰ 鼓声停了！花停在 @小红 手上，接受惩罚吧～
🎉 其余玩家成功脱身
```

### 指令设计

| 指令 | 权限 | 说明 |
|------|------|------|
| `击鼓传花` | 授权用户 | 初始化游戏（清空玩家列表） |
| `加入` / `+`、`退出` / `-` | 全员 | 参与 / 退出（准备阶段） |
| `开始` | 授权用户 | 随机排序并开始（≥2 人），启动倒计时 |
| `<数字>` | 当前玩家 | 输入「花」的数字，传给下一位 |
| `结束` | 授权用户 | 强制结束（进行中）/ 停止（准备中） |

### 实现要点

- **复用 `number_bomb` 的成熟结构**：玩家列表、授权校验、准备/进行状态机、Web UI 状态行、`_do_xxx` 共用操作（聊天与 Web 共用）
- **「花」的机制**：每次传递重新生成随机 5 位数字，**仅提示当前玩家**（公屏只说「需要输入上面那串数字」——实际公屏会显示，若需保密可改为私信或仅显示给当前玩家，见「待定问题」）
- **倒计时**：`每 5 名玩家 1 分钟`（参考原版）或固定时长，可配置；到点自动结束判负
- **计时器生命周期**：开始/结束时创建与取消 `asyncio.Task`，`terminate()` 中清理，避免插件禁用后仍在计时（`number_bomb` 的 timer 处理可参考）
- **计分**：输家扣分或其余玩家加分（可选，接计分榜）
- **可选增强**：传递时带趣味文案（「花在小明手里炸开了！」）、鼓声音效符号（`🥁` 逐次加速）

### 配置项草案

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `cmd_start_game` / `cmd_join` / `cmd_quit` | `击鼓传花` / `加入,+` / `退出,-` | 指令名 |
| `time_limit_mode` | `per_players` | 时限模式：`per_players`（每 N 人 T 分钟）/ `fixed`（固定秒数） |
| `minutes_per_players` | `1` | per_players 模式下，每多少名玩家 1 分钟 |
| `fixed_timeout` | `60` | fixed 模式下的秒数 |
| `number_digits` | `5` | 「花」的数字位数 |
| `score_enabled` | `true` | 是否计分 |

### 待定问题（开发前确认）

1. **「花」是否公开**：原版直接发在公屏（所有人都能看到，靠手速），若要「只有当前玩家知道」需走私信（机器人私信权限 + 平台限制待确认）
2. **输家惩罚**：仅播报 / 扣分 / 让主播唱歌等自定义文案
3. **是否支持连麦多房**（跨房玩家参与）

## 通用约定

所有新插件遵循以下约定（与现有插件保持一致）：

- **目录结构**：`main.py` / `metadata.yaml` / `_conf_schema.json` / `_ui_schema.json` / `README.md`
- **配置分组**：`_conf_schema.json` 中使用 `group` 字段（`常用` / `文案` / `显示` / `高级`）
- **文案可配置**：所有对用户输出的文案都放进配置项，支持 `{name}` 等占位符
- **日志**：仅保留有价值的输出——生命周期节点、用户操作审计、错误/警告；常规路径不打日志（见日志噪音策略）
- **Web UI**：状态类插件提供 `_ui_schema.json`（表格 + 行内操作），复用 `list` 类型多值输入等已有能力
- **事件处理**：聊天指令与 Web 操作共用 `_do_xxx` 方法，行为一致
- **测试**：用真实框架（`PluginManager` 加载 + `MessageEvent` 派发）写端到端脚本，覆盖边界（权限、状态机、并发/计时）
- **打包**：随插件生成 `<name>.zip`（含除 `__pycache__` 外的全部文件），版本号写入 `metadata.yaml`
